# PHASE 6D-3A — Admin Products: List + Details + Edit

**Status: IMPLEMENTED and STATICALLY VERIFIED. NOT runtime-tested** — no connection to the real Supabase project was
available, so no page was ever rendered against real data and no RPC was called.

No database changes.

## 1. Features completed

- `/admin/products` — server-side search, status filter (all / active / inactive), category filter, pagination
  (25 per page), loading skeleton, empty state (with and without filters), error state, 403 state. List state lives in the
  URL (`?q=&status=&category=&page=`); unknown or malformed values are dropped.
- `/admin/products/$productId` — overview (image, status, stock, category, price, compare-at, timestamps), edit form,
  variants table. Loading, not-found (also for a malformed id, which is never sent to the database), 403 and generic
  error states with retry.
- Edit product: name, URL slug, category, description, brand, SKU, price, compare-at price, unit label — exactly the
  fields `admin_update_product()` accepts. Sends a PATCH of only the changed fields. Submit disabled until something
  changed and while saving; double-submit guarded (ref + disabled); success toast; field-level validation messages;
  server refusals (duplicate slug/SKU, unknown category, invalid value) shown as field-level generic messages.
- Edit variant (dialog): name, SKU, price, compare-at, position — exactly the catalogue fields
  `admin_update_product_variant()` accepts (minus `is_active` and `attributes`, see decisions).
- "Changed elsewhere" notice: if a background refetch shows a newer `updated_at` than the form was loaded from, the form
  offers "Discard my edits and load latest". Edits in progress are never silently overwritten.
- Prices are typed in major units and converted to integer cents by string arithmetic (no floats).
- Products nav entry is now a live link.

## Decisions worth a look

- **Admin-only, not staff.** The existing mechanism (`is_admin` in the layout, `require_admin()` in every RPC) admits
  admins only; staff are refused. I reused it as instructed rather than widening it.
- **Slug is editable** because the backend allows it; the form warns that it changes the storefront address.
- **Variants are editable, but not `is_active`, `attributes` or stock.** The brief lists "existing supported variants" as
  possible edit fields but forbids activation mutations in this phase, so variant activation is read-only here.
- **Read-only on purpose:** active status, stock (`in_stock` + quantity, shown as stored) and the image.
- **No concurrency token in the backend:** two admins saving the same product is last-write-wins. The "changed
  elsewhere" notice reduces the risk but cannot prevent it.
